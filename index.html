The Chrome extension

Every page you work on, ready for feedback.

No install in your codebase, no build step: the extension brings the whole kit to the sites you choose — your local dev server, a staging link, production.

One switch per site

Nothing runs until you turn it on. Click the icon, flip the switch for the site you are on, and the toolbar waits in the corner of the page.

  • Chrome asks for that one site, at the moment you switch it on
  • Switching a site off hands the permission back
  • “On every site” when you would rather not switch each one (Pro)
  • The popup tells you how many notes are waiting on this page

Point and note

Click an element, write what should change, choose Improvement, Fix or Design. A numbered marker stays on the element, even when the page reflows or you resize the window.

  • Every note carries the element — selector, path, component — the page and the screen size
  • Take a screenshot of the element with the camera button
  • “Your feedback” lists every note, to review, reveal or drop

Design mode

Restyle the real element where it stands — colours, type, spacing, radius, shadow — and design its hover, focus, active and disabled states too. Every tweak becomes an instruction for your agent.

  • Switch any tweak off to compare before and after
  • The page's own colours and typefaces, offered first
  • Contrast checked against what is actually behind the text

Phone and tablet

The page reopens in a real 390 px or 834 px frame, so the browser applies the mobile layout — not a squeezed desktop. Annotate it right there.

  • Desktop, Tablet, Phone, one click apart
  • Each note records the width it was written at, because “make this smaller” means opposite things at 1440 and at 390
Connect your agent

Your agent sets itself up.

Press Copy setup prompt and paste it into Claude Code, Cursor, Codex, VS Code or any MCP client. The agent installs the connection and checks it on its own; the popup turns to Connected.

  • On your local dev sites, each note reaches the agent as you write it — then just ask it to “check my notes”
  • Screenshots reach your agent too: tick “Let my agent see screenshots” and each one is saved in Downloads › Annotate Kit, so the brief can point to the file. Cleaned up after 7 days.
  • No agent? Copy puts the whole brief on your clipboard; Send posts it to a webhook you choose

Why

Your agent cannot see what you are pointing at.

Coding agents are good at changing code and blind to the screen. Every design review turns into an exercise in describing pixels in prose — and the agent edits the wrong component, or asks three questions before touching anything.

What you send today

"hey can you make the card on the pricing page a bit lighter, and the heading is too big on mobile — not that card, the one with the chart"

Screenshot attached. Three follow-up questions. Two wrong files touched.

What Annotate Kit sends

div.hero-card · <Landing>
pages.tsx:44 · written at Phone · 390px
background-color: #FFFFFF → var(--paper)

The element, its component, the source line, the screen width, the exact value.

Who it is for

So designers can finally ship the change themselves.

Vibe-coding works right up to the moment you have to describe a screen in words. A designer knows exactly what is wrong and cannot say it in a way an agent can act on; a developer can say it and did not notice it. Annotate Kit removes the translation step: you point at the thing, and the agent receives the thing.

Designers

Change it live in the inspector, in your own palette and your own type scale. What you send is not an opinion, it is a diff waiting to be applied.

Everyone who is not technical

Product, marketing, support, a client on a call. Click, write a sentence, done — no selector, no screenshot, no "second card from the left".

Developers

Feedback arrives with the element, the component and the screen size already attached. No triage, no going back for the missing half of the question.

Why it costs less

A precise brief is a cheap brief.

An agent that does not know which element you mean has to go and find out: grep the repo, open candidate files, read components, guess, ask, try, be told it is the wrong one, try again. Every one of those steps is tokens in and tokens out — and the search is the expensive part, not the fix. Hand it the selector, the component, the source line and the exact before/after value, and there is nothing left to search for.

      For developers

      Rather have it in your own app? There is a package.

      The same kit ships as annotate-kit on npm: mount it on your running site, React, Vue, Svelte or plain HTML, and decide where the brief goes — clipboard, your own callback, an HTTP endpoint or a local agent server.

      Install

      # react and react-dom are peer dependencies since 0.3.0
npm install annotate-kit react react-dom

# writes your config and a brief for your own agent
npx annotate-kit init
      import { createAnnotateKit } from 'annotate-kit';

createAnnotateKit({ locale: 'en' }).mount();

      No bundler? dist/standalone.global.js drops into a <script> tag and exposes window.AnnotateKit — no React needed for that one.

      Update

      npm install annotate-kit@latest
# says what moved in the contract, before anything breaks
npx annotate-kit upgrade

      The package publishes a versioned contract — the API, DOM attributes and extension points that do not break inside a major version — so taking an update is a version bump, not a merge.

      What is new in 0.3.0

      • Screenshots reach your agent on every path: saved with a file path for a local agent, and carried as image data in webhook payloads.
      • Follows the page's colour scheme — the default theme is now auto; set theme: 'dark' for the old look.
      • Redesigned panels, one style: “Your feedback”, settings, inspector and device frame share one stylesheet.
      • New options: endpoint to sync with a local agent server, settings: false for production, accentGradient, and before/after toggles for design changes.
      • English and French overlay text, and an accessible name on every icon-only control.
      • Fixes: the kit no longer annotates its own interface, markers stay on their element on reflow and resize, and a run of inspector and spacing bugs.
      • Breaking: react and react-dom (≥ 18) are now peer dependencies. The package went from 4.1 MB to 0.6 MB.

      0.3.0 is on its way to npm; until it lands, npm install gives you 0.1.0.
